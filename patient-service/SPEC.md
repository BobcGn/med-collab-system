# 患者业务与访问边界

## 职责

拥有患者档案、查询与统计，以及就诊、转诊、状态、生命体征和医疗信息操作。路由负责接入，PatientService 负责业务判断，repository 负责存储；用户信息补充通过 AuthClient 获取。

## 边界与限制

患者业务不执行影像推理，不生成模型解释或正式 PDF，不直接操作其他服务的数据表。跨模块依赖见 `med-collab-architecture`。

接口已有 JWT 认证和部分角色规则，但不同操作的资源授权不一致；医院/患者 ID 由调用方提供，不能把认证成功等同于允许读取或修改任意医院的患者。AuthClient 中存在访问判断函数，但当前未贯穿所有读写路径。

用户已确认真实医院场景下的身份范围校验仍需补强。现阶段规格不承诺院际隔离已成立，也不把前端筛选作为授权。删除、批量操作与附属医疗记录修改应和普通患者读写采用同一资源范围原则；具体院方授权矩阵尚未确认。
