# 网关转发与边缘认证

## 职责

为浏览器 REST 提供统一转发入口，根据服务配置路由并处理路径映射、转发头和响应。部分业务前缀在边缘要求 JWT，auth 前缀转发后由下游区分公开与受保护操作。

## 边界与限制

网关不拥有业务数据、分割模型或报告生成规则；下游仍须负责资源级授权，网关验签不能代替医院/患者范围检查。真实调用方向由 `med-collab-architecture` 描述。

当前没有 WebSocket 代理；客户端有直连路径，不能把网关视为唯一安全边界。转发实现不携带 DELETE 请求体，依赖裸 ID 数组的批量删除不能声称经网关可用；独立 report 默认目标为8084，并非 metric 别名。压缩/大文件、跨容器路径和部署前缀仍需集成验证；当前不宣称所有转发方法及 Docker 拓扑已正确验收。

公开调试入口会记录/拟回显认证信息，metrics 路由也只是占位文本，不能充当安全验签或完整可观测性。具体映射和异常由 [API 参考](API.md)维护，安装插件或 CORS 放行不意味着端点能力已经实现。
